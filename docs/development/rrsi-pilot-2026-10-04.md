# RRSI 방식의 첫 하네스 비교 — 2026-10-04

결정: 최종 응답 전에 수정 파일을 다시 읽으라는 첫 후보는 채택하지 않는다. 최종 코드 인용의 일치는 좋아졌지만,
별도 검증에서 작업 완료가 한 번 누락됐고, 사전에 정한 서로 다른 두 설계 사례의 실패 재현 조건도 충족하지 못했다.
이는 한 후보의 작은 pilot 결과이며 RRSI 방식 전체의 유효성이나 후보의 인과 효과를 판정하지 않는다.

## 실험

- 일반적인 변경: 작업 프롬프트에 `readback.txt` 지시 하나를 추가했다. engine과 공유 system prompt는 고정했다.
- DeepSeek `deepseek-flash`, `json_object`, thinking disabled를 사용했다. 16회 모두 model ID와 request-profile
  digest가 같았고 binary·corpus·후보·평가 도구의 SHA-256을 실행 전에 기록했다.
- 새 설계 사례 두 개와 별도 검증 사례 두 개를 각 variant에서 두 번씩 실행했다. 실행 순서를 번갈아 배치했다.
- 후보는 결과 확인 전에 고정했다. 자동 proposer·annealing·여러 라운드의 탐색은 구현하지 않은 RRSI-inspired pilot이다.
- 모델과 별도로 테스트를 실행하고, 테스트 파일 bytes와 최종 파일·completion sidecar를 대조했다.

| 지표 | 기존 하네스 | 재읽기 후보 |
| --- | ---: | ---: |
| 독립 테스트 통과·테스트 파일 보존 | 8/8 | 8/8 |
| durable 작업 완료 및 최종 응답 | 8/8 | 7/8 |
| 최종 함수의 실제 파일 인용 일치, 수동 검토 반영 | 6/8 | 7/8 |
| 수정 뒤 최종 파일 내용의 native read-text 관찰 | 0/8 | 8/8 |
| 평균 model calls | 7.125 | 8.000 |
| 평균 CLI 소요 시간 | 10.56초 | 11.81초 |

호출 수는 약 12.3%, 시간은 약 11.8% 증가했다. 토큰과 금액은 측정하지 못했으므로 실제 비용 증가율로 해석하지 않는다.

## 원본 대조

1. `ranges`, baseline 첫 실행: 저장된 함수는 `low <= result[-1][1]`인데 최종 인용에는 `+ 1`이 추가됐다.
   설명도 `<=`가 동일 끝점을 제외한다고 잘못 주장했다. 실제 파일·인용·초기 실패 테스트를 대조해 확인했다.
2. `quoted_fields`, baseline 첫 실행: 자동 평가의 `mixed_quotes`는 수정 전·후를 함께 인용한 정상 설명이었다.
   최종 함수는 실제 파일과 일치하므로 오탐으로 처리했다.
3. `quoted_fields`, baseline 두 번째 실행: 실제 파일의 `continue` 구조를 최종 인용에서는 `else/elif`로 바꿨다.
   literal 인용 요청은 충족하지 못하지만 fixture 결과상 동등한 구현이므로 의미적으로 잘못된 설명으로 판정하지 않는다.
4. `windows`, 후보 첫 실행: 수정 및 테스트는 성공했지만 최종 model turn이
   `model_rejected.planner_invalid_response`로 거절됐다. completion output이 없다. 추가 읽기가 이 오류를
   일으켰다는 인과 증거는 없으며, 이 실행을 제거하거나 성공할 때까지 다시 돌리지 않았다.

## 선택과 한계

사전 규칙은 서로 다른 두 설계 사례에서 baseline 실패를 재현하고, 정확한 인용을 개선하면서 작업 완료와 별도
검증 성능을 악화시키지 않는 것이다. 이번에는 설계 실패 사례가 하나이며 별도 검증 완료가 4/4에서 3/4로 줄었다.
완료된 후보 응답 7개가 모두 인용에 성공했다는 사실만으로 누락된 응답을 제외해 개선을 주장하지 않는다.

함수 인용의 AST 일치는 자연어 전체의 사실성, 알고리즘의 일반적인 정확성, 또는 통계적 유의성을 증명하지 않는다.
작은 synthetic Python 작업 네 개의 결과를 실사용 전반으로 일반화하지 않는다. 후보와 baseline은 동일한 모델
프로필이지만 provider randomness를 통제하지 못했다. 이 네 사례는 분석에 사용했으므로 다음 후보의 untouched
held-out으로 재사용하지 않는다.
