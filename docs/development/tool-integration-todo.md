- [ ] **xgen:** 큰 enum 값·중첩 schema의 상세 조회 필요성과 생략이 모델 선택에 주는 영향을 평가하고, 필요하면 전체 계약 digest에 묶인 제한된 상세 조회를 추가한다. 입력 목록 페이지와 schema 상세 조회를 구분한다.
- [ ] **추론 모델·SEV:** 전달된 올바른 후보/계약에서의 선택·거절 품질을 별도 평가. 모델/프롬프트 개선과 xgen 역할 연결 개발을 구분한다.
- [x] **xgen:** 검색 결과·오류 코드를 구분하고, worker 실패·시간/출력 한도·Ctrl+C·자식 프로세스 정리를 검증. 빈 후보에서 업무 도구를 실행하는 경로는 없다.

완료 기준: xgen에서 자연어 요청으로 외부 도구 후보와 정확한 스키마를 얻는다. 두 독립 명세에서 동작하고, 전체 목록 제공과 검색 경로의 비용·후보 포함률을 비교할 수 있다.

## 3. API 조회 실행과 사용자 연결 흐름

- [x] **xgen:** `xgen.http/read` 프록시로 exact 외부 도구·입력·계약·target을 기존 권한·실행·Receipt·완료 검증 경로에 연결. 개별 외부 Definition/Instance 자동 admission은 2번 후속이다.
- [x] **xgen:** 원본 로컬 JSON 명세 보존과 GET scalar path/query·2xx JSON 응답·bearer/no-auth 어댑터 구현. 조회 효과는 `connect --allow-get`으로 지정하고 Run read 승인을 유지한다.
- [ ] **graph-tool-call:** 원격 URL/Swagger UI 수집 원본·출처 보존의 공개 계약을 검토·개선. 정규화된 발견 계약과 완전한 실행 계약을 구분한다.
- [ ] **xgen:** 원격 원본 수집 계약을 연결하고 기존 collection 실행 이행·연결 점검을 제공. header/body/배열·인증 방식의 HTTP 어댑터 지원을 확대한다. 지원하지 않는 계약을 추측해 호출하지 않는다.
- [x] **xgen:** `tools connect` 주소·숨김 bearer 입력/OS secret store·환경 참조·불변 연결 저장·재사용 구현. 인증값은 그래프·worker·모델·Receipt에 넣지 않는다.
- [ ] **xgen:** 원격 명세·지원 operation·인증 연결 점검, 연결 수정/삭제 UX와 실제 OS secret store backend 검증. collection 삭제·재빌드 명령(backend 버전을 올리면 기존 collection을 다시 import해야 함)도 포함한다.
- [x] **평가:** 보류한 두 독립 fixture에서 검색 → describe → 실제 loopback GET → 검증 body 기반 최종 응답·완료 재생 확인. 모델은 결정적 endpoint이며 LLM 품질 비교가 아니다. 승인·입력/계약/연결 drift 차단과 실행 중 kill 후 중복 방지도 검증했다. [범위·명령·한도](http-read-tools.md).
- [ ] **평가:** 실제 LLM·접근이 허용된 live 시스템의 조회 성공률·응답 정확성과 호출/토큰/시간/비용 비교.
- [ ] **명세 없는 시스템의 API 복원:** Swagger가 없는 웹 서비스의 API를 클릭·트래픽 없이 찾아 OpenAPI 초안으로 만들고 기존 `tools import` 경로에 넣는다. 우선순위는 백엔드 코드·프레임워크 라우트(Spring springdoc·`/actuator/mappings`) > 프론트 번들 정적 분석 > 서버 접근 로그 > 자동 화면 탐색. 고객 시스템은 계약서에 대상·방법·데이터 처리를 명시한 범위에서만 한다.
  - 2026-10-09 PoC(프론트 번들 정적 분석, 공개 앱): acorn AST로 호출 지점(verb member call·url 설정 객체·fetch)을 찾고, 압축 후 남은 메서드 이름과 호출 주변 코드를 LLM 한 줄 설명으로 보강했다. 설계 2개(listmonk, Shlink)와 별도 subagent가 고른 동결 검증 2개(Kavita, Traccar), 앱마다 질의 24건.

완료 기준: 도구별 JSON 설정 없이 재사용 가능한 연결로 조회 작업을 완료한다. 실제 API 실행 결과와 Receipt를 제시할 수 있다. fixture 검증과 live 검증은 각각 표시한다.

## 4. 브라우저 관찰·실행과 SEV 연결

- [ ] **브라우저 어댑터:** browser-use가 필요한 관찰·동작·결과 계약을 제공하는지 코드로 확인하고 최소 연결 구현. 기존 agent-browser 구현을 비교 자료로 활용.
- [ ] **SEV:** 현재 화면 + 요청 + 후보를 typed-choice로 전달. 후보 밖 선택, 후보 없음, 낮은 확신, 추가 관찰·질문 전환 처리 검증.
- [ ] **xgen + 브라우저:** 스냅샷 버전 검사, 동작 후 재관찰, stale-ref 거절, 중단·실패 기록 연결.
- [ ] **브라우저:** 가려진 요소·접힌 검색창·탐색 후 바뀐 화면 등 일반 실패를 재현하고 실행기 개선 과제 분리.
- [ ] **평가:** 기존 브라우저 경로와 SEV 선택 경로를 같은 관찰·후보·실행기 조건에서 비교. 평가 정답을 후보 구성에 사용하지 않는다.

완료 기준: 서로 다른 화면에서 조회·검색을 수행하고 실제 결과를 확인한다. '없는 대상'과 '오래된 요소 ref'는 잘못된 클릭으로 이어지지 않는다. 화면 선택 정확도와 업무 완료율을 별도로 기록한다.

## 5. API·화면 도구를 한 그래프로 통합

- [ ] **화면 변환 어댑터:** 관찰 정보를 재사용할 작업 정의로 변환. 임시 요소 refs는 스냅샷 실행 바인딩에만 둔다.
- [ ] **graph-tool-call:** API와 화면 작업을 함께 검색하고, 이동·필수 입력·값 전달 관계에 출처·근거·검증 상태를 보존.
- [ ] **xgen:** API 결과 → 화면 검색, 화면 결과 → API 조회의 값 전달과 실제 완료 검증 연결.
- [ ] **평가:** 일반 브라우저 탐색과 그래프 참고 탐색 비교. 그래프 효과와 SEV 효과를 별도 실험으로 분리.
- [ ] **xgen:** 효과가 시작된 API 실패를 브라우저로 자동 재실행하지 않도록 재개·중복 방지 검증.

완료 기준: 두 시스템의 새 검증 사례에서 API·화면 도구를 섞은 조회 작업을 완료하고, 선행 관계가 단순 추론인지 실행으로 확인됐는지 구분한다.

## 6. 역할별 모델 확장과 음성

- [ ] **xgen + SEV:** 추론·판단 모델을 독립적으로 교체하거나 같은 모델에 연결하는 설정과 호출 예산·타임아웃 구현.
- [ ] **STT 어댑터:** 누적 partial·최종 전사 계약, 중복 처리 방지, 중단·새 요청 경계 구현. 텍스트 사용은 STT 없이 동작.
- [ ] **xgen:** 음성 요청 → 기존 도구 실행 흐름 연결. 필요할 때 TTS·화면 해석 역할 확장.
- [ ] **평가:** 단일 모델과 역할 분리 구성을 동일 작업에서 비교. SEV의 API/UI 체크포인트 호환성을 별도로 검증.

완료 기준: `xgen` 안에서 역할별 모델을 바꿀 수 있고, 전체 지연·역할별 호출 비용·작업 완료율을 측정한다. 모델 수가 늘었다는 이유만으로 기본 채택하지 않는다.

## 7. 배포·기본값 결정

- [ ] **xgen:** 지원 OS별 내부 도구 설치·자동 실행·업데이트·버전 호환 검증.
- [ ] **xgen:** 작업 중 상태와 최종 응답 중심 UX 제공. 연결 실패·인증 만료·모델/도구 부재의 해결 경로 표시.
