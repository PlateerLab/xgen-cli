# xgen CLI 도구·모델 통합 TODO

갱신: 2026-10-06 (KST)

이 파일은 공동 개발 작업 목록의 정본이다. 방향과 확인된 사실은 [MEMORY.md](../../MEMORY.md), SEV·브라우저 검토 근거는 [통합 검토](browser-tool-graph-sev-2026-10-06.md)를 참조한다. 모든 개발 항목은 일반 기능이다. 시스템별 명세·업무 규칙·인증 설정은 별도 입력으로 관리한다.

목표: 사용자는 `xgen`에서 시스템을 한 번 연결하고 자연어로 요청한다. 내부에서는 API·화면 도구를 찾고, 필요한 모델을 호출하고, 실제 결과를 검증해 최종 응답을 제공한다.

## 0. 검토한 기반

- [x] 현재 Registry·Router와 의미 기반 tool search의 차이 확인. xgen에 검색 계층은 아직 없다.
- [x] graph-tool-call로 실제 명세 수집·그래프 생성·조회 요청 검색을 별도로 실행. 검색 품질 문제도 기록.
- [x] SEV의 API 후보 선택·UI 판단 계약과 기존 agent-browser 경로 검토.
- [x] 공동 개발 메모와 작업 시작 시 읽을 안내 작성.

위 완료 항목은 검토·별도 테스트다. xgen 내장 통합 완료를 뜻하지 않는다.

## 1. 공통 계약과 첫 검증 계획 — 가장 먼저

- [x] **xgen:** 기존 CapabilityDefinition / CapabilityInstance를 기준으로 외부 도구 매핑 설계. 발견 참조와 실행 계약의 경계를 [내부 검색 계약](internal-tool-search.md)에 기록했다. 실행 admission 구현은 후속이다.
- [x] **xgen + 도구 어댑터:** 발견용 snapshot 참조·계약 보존과 실행용 바인딩·효과·인증의 분리 규칙 정의. discovery 결과는 아직 실행용 schema-conformant Definition이 아니다.
- [x] **xgen + 브라우저:** 관찰 계약 후보와 영구 도구/임시 ref 분리를 문서화. 실제 wire schema·브라우저 어댑터 검증은 4번에서 수행한다.
- [x] **xgen + SEV:** 추론·판단·STT의 역할별 입출력과 공유/분리 바인딩 설계를 문서화. 실제 모델 연결은 6번에서 수행한다.
- [ ] **평가:** 서로 다른 두 시스템의 설계 사례와 별도로 보류한 검증 사례 선정. 먼저 독립적인 명세 fixture로 개발하고 실제 명세 접근이 가능할 때 live 검증한다.
- [ ] **평가:** 비교 방법·성공 조건·비용 한도·호출/시간 예산·채택 기준을 결과 확인 전에 고정한다. 모델 비교는 SEV 규칙에 따라 사전등록한다.

완료 기준: API 도구와 화면 작업을 기존 실행 계약에 어떻게 연결할지 문서·작은 fixture로 설명할 수 있고, 검색·판단 결과가 실행 권한을 만들지 않는다.

## 2. graph-tool-call을 내부 검색 기능으로 연결

- [x] **xgen:** 포함된 Python worker·stdin/stdout JSON·uv 자동 준비 구현. 별도 서버는 없고 개발 버전의 uv 의존은 남았다. 완전한 포함 배포·OS 검증은 7번이다.
- [x] **graph-tool-call + xgen:** `tools import/search/describe/list` 구현, 0.46.0 고정, 압축·불변 snapshot·digest 검증. 두 명세 fixture와 기존 실제 명세 snapshot으로 동작 확인.
- [x] **xgen:** agent loop에 검색·조회 built-in Capability 두 개를 등록해 후보와 원본 계약을 단계적으로 제공. manifest의 collection digest·exact request를 검증하고 승인·material 복구·Receipt에 연결했다. 재개는 같은 snapshot 목록을 유지한다.
- [ ] **xgen:** 발견한 외부 도구 자체의 실행용 Definition/Instance admission. 검색·조회 built-in의 등록과 구분하며 HTTP adapter·효과·인증 검증을 3번과 함께 구현한다.
- [ ] **xgen:** 컨텍스트에 들어가는 소규모 목록의 직접 제공을 유지하고, 검색 경로 선택은 설정·평가 근거로 정한다.
- [ ] **graph-tool-call:** 유사한 도구 혼동·빠진 선행 도구를 새 사례에서 평가. 임베딩 없는 검색과 임베딩 추가를 별도로 비교한 뒤 기본값 결정.
- [x] **xgen:** 검색 결과·오류 코드를 구분하고, worker 실패·시간/출력 한도·Ctrl+C·자식 프로세스 정리를 검증. 빈 후보에서 업무 도구를 실행하는 경로는 없다.

완료 기준: xgen에서 자연어 요청으로 외부 도구 후보와 정확한 스키마를 얻는다. 두 독립 명세에서 동작하고, 전체 목록 제공과 검색 경로의 비용·후보 포함률을 비교할 수 있다.

## 3. API 조회 실행과 사용자 연결 흐름

- [ ] **xgen:** 검색된 API 도구를 기존 권한·실행·Receipt·완료 검증 경로로 연결.
- [ ] **xgen:** 명세의 HTTP 파라미터 위치·본문·응답·인증 요구를 보존하는 어댑터 구현. 도구 설명이나 annotation만으로 효과를 신뢰하지 않는다.
- [ ] **xgen:** 주소 입력·로컬 인증·연결 저장·재사용 흐름 제공. 인증 정보는 그래프·모델 컨텍스트에 넣지 않는다.
- [ ] **평가:** 두 시스템의 조회 작업에서 자연어 요청 → 검색 → 실행 → 근거 있는 최종 응답 검증.

완료 기준: 도구별 JSON 설정 없이 재사용 가능한 연결로 조회 작업을 완료한다. 실제 API 실행 결과와 Receipt를 제시할 수 있다. fixture 검증과 live 검증은 각각 표시한다.

## 4. 브라우저 관찰·실행과 SEV 연결

- [ ] **브라우저 어댑터:** browser-use가 필요한 관찰·동작·결과 계약을 제공하는지 코드로 확인하고 최소 연결 구현. 기존 agent-browser 구현을 비교 자료로 활용.
- [ ] **SEV:** 현재 화면 + 요청 + 후보를 typed-choice로 전달. 후보 밖 선택, 후보 없음, 낮은 확신, 추가 관찰·질문 전환 처리 검증.
- [ ] **xgen + 브라우저:** 스냅샷 버전 검사, 동작 후 재관찰, stale-ref 거절, 중단·실패 기록 연결.
- [ ] **브라우저:** 가려진 요소·접힌 검색창·탐색 후 바뀐 화면 등 일반 실패를 재현하고 실행기 개선 과제 분리.
- [ ] **평가:** 기존 브라우저 경로와 SEV 선택 경로를 같은 관찰·후보·실행기 조건에서 비교. 평가 정답을 후보 구성에 사용하지 않는다.

완료 기준: 서로 다른 화면에서 조회·검색을 수행하고 실제 결과를 확인한다. '없는 대상'과 '오래된 요소 ref'는 잘못된 클릭으로 이어지지 않는다. 화면 선택 정확도와 업무 완료율을 별도로 기록한다.

## 5. API·화면 도구를 한 그래프로 통합

- [ ] **화면 변환 어댑터:** 관찰 정보를 재사용할 작업 정의로 변환. 임시 요소 refs는 스냅샷 실행 바인딩에만 둔다.
- [ ] **graph-tool-call:** API와 화면 작업을 함께 검색하고, 이동·필수 입력·값 전달 관계에 출처·근거·검증 상태를 보존.
- [ ] **xgen:** API 결과 → 화면 검색, 화면 결과 → API 조회의 값 전달과 실제 완료 검증 연결.
- [ ] **평가:** 일반 브라우저 탐색과 그래프 참고 탐색 비교. 그래프 효과와 SEV 효과를 별도 실험으로 분리.
- [ ] **xgen:** 효과가 시작된 API 실패를 브라우저로 자동 재실행하지 않도록 재개·중복 방지 검증.

완료 기준: 두 시스템의 새 검증 사례에서 API·화면 도구를 섞은 조회 작업을 완료하고, 선행 관계가 단순 추론인지 실행으로 확인됐는지 구분한다.

## 6. 역할별 모델 확장과 음성

- [ ] **xgen + SEV:** 추론·판단 모델을 독립적으로 교체하거나 같은 모델에 연결하는 설정과 호출 예산·타임아웃 구현.
- [ ] **STT 어댑터:** 누적 partial·최종 전사 계약, 중복 처리 방지, 중단·새 요청 경계 구현. 텍스트 사용은 STT 없이 동작.
- [ ] **xgen:** 음성 요청 → 기존 도구 실행 흐름 연결. 필요할 때 TTS·화면 해석 역할 확장.
- [ ] **평가:** 단일 모델과 역할 분리 구성을 동일 작업에서 비교. SEV의 API/UI 체크포인트 호환성을 별도로 검증.

완료 기준: `xgen` 안에서 역할별 모델을 바꿀 수 있고, 전체 지연·역할별 호출 비용·작업 완료율을 측정한다. 모델 수가 늘었다는 이유만으로 기본 채택하지 않는다.

## 7. 배포·기본값 결정

- [ ] **xgen:** 지원 OS별 내부 도구 설치·자동 실행·업데이트·버전 호환 검증.
- [ ] **xgen:** 작업 중 상태와 최종 응답 중심 UX 제공. 연결 실패·인증 만료·모델/도구 부재의 해결 경로 표시.
- [ ] **공동 개발:** 각 저장소 변경·커밋·호환 버전과 남은 문제 연결. 메모와 TODO에는 결과·상태만 갱신하고 상세 증거는 실험 문서에서 관리.
- [ ] **평가:** 검증 결과로 검색·모델 분기 기본값 결정. 작업 성공률, 잘못된 실행·완료 주장, 호출·토큰·금액, 단계·시간을 기준으로 판단.

첫 구현 묶음은 **1번 계약·검증 계획 + 2번 최소 검색 연결**이다. 모델 재학습, STT 통합, 변경·등록 업무 자동화는 후속 단계다.
