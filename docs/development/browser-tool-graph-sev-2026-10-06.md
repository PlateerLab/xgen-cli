# 브라우저·도구 그래프·SEV 통합 검토

작성: 2026-10-06 (KST). 상태: 로컬 문서·코드 검토와 통합 제안. 새로운 실행 실험이나 모델 비교는 수행하지 않았다.

## 사용자가 정한 범위

xgen CLI가 API와 브라우저 도구를 함께 사용하고, graph-tool-call로 도구와 관계를 구성·검색한다. SEV의 기존 화면 판단 경로도 함께 검토하고 재사용 가능성을 평가한다. 각 도구의 개선과 비용은 별도로 추적한다.

## 현재 SEV 사용 방식

SEV는 자유롭게 브라우저 명령을 생성하는 모델이 아니라, 제공된 상태와 선택지에 대해 선택을 반환하는 판단 모델이다.

- `SonAIengine/sev:src/sev/protocol.py`: 요청은 `state`와 `questions`; 각 질문은 `criteria`에 선택지 ID와 설명을 담는다. 응답은 `choice`, 선택적인 `confidence`와 `probabilities`다. 후보 밖 선택은 모델 오류로 거절하며 다시 시도할 이유로 취급하지 않는다.
- `src/sev/tasks/ui/rows13.py`: E13 상태는 `Page → Screen → User said` 순서다. 화면 줄은 요소 ID, 역할, 이름, 가능한 경우 위치를 담는다. 요소 질문의 선택지는 ID다. 입력할 문구는 단어별 yes/no 판단을 이용하는 별도 경로가 있다.
- `src/sev/tasks/ui/bench13.py`: 많은 요소를 나눠 판단하고 승자끼리 다시 선택한다. 일부 화면 구성은 정답을 포함하도록 만드는 평가용 코드다. 이 `must=gold` 경로를 실제 후보 생성이나 새로운 검증에 재사용하면 정답 유출이다. 이 파일에는 기존 다른 세션의 로컬 변경이 있어 수정하지 않았다.
- `docs/design/DEX_VOICE_INTEGRATION.md`: 문서상 DeX 흐름은 STT → 준비 여부·요청 경계 → 화면 스냅샷 → 요소 선택 → click/fill이다. 준비 선택지는 `act_now / wait / not_ui`다. 판단 중 스냅샷을 고정하고 오래된 참조는 재관찰한다. 위험 동작은 확인 경로로 넘긴다.
- `scripts/web/crawl.py`: 실제 수집 코드는 `agent-browser snapshot -i`를 호출하여 접근성 스냅샷과 refs를 저장한다.

중요한 구분: 이 경로의 실행기는 **agent-browser**다. 사용자가 앞으로 활용하려는 **browser-use**와는 별도 프로젝트다. 실행기 교체 가능성은 공통 관찰·동작 계약으로 검토해야 한다.

검토 환경의 DeX에는 `BrowserSnapshot`과 ref 기반 `BrowserInteract` 도구 정의, `generation` 전달 및 재연결 후 stale-ref 거절 코드가 있다. 문서에 적힌 음성 실험 브랜치 `exp/voice-fast-act`는 이 환경에서 찾지 못했다. 따라서 해당 브랜치의 최신 실행 구현이나 현재 모델 서버 상태까지 확인했다고 주장하지 않는다.

## API 도구 선택에도 이미 쓰인 SEV

- `scripts/x2bee/gtc_tools.py`: graph-tool-call로 후보를 검색하고 도구명, endpoint, 설명, 태그를 정리하는 평가 연결 코드가 있다. graph-tool-call 자체는 SEV의 필수 의존성으로 묶지 않고 별도 환경에서 사용한다.
- `docs/results/E4_X2BEE_TOOL_SELECTION_20260927.md`: 미학습 영역 1,043개 요청에서 올바른 도구 선택률은 검색 첫 후보 18.1%, SEV 43.0%였다. 반면 사람이 작성한 키워드 사례 19개에서는 검색 첫 후보 94.7%, SEV 87.7%였다. SEV를 항상 추가하면 좋아진다는 근거는 아니다. 이 END2END는 실제 API 실행 성공률이 아니라 올바른 도구 선택률이다.
- `docs/results/E6_X2BEE_ROUTING_FIXES_20260928.md`: 검색 후보에 태그 후보를 더하는 혼합 경로는 같은 시험에서 선택률 48.4%, 후보의 정답 포함률 82.0%였다. 모델 호출 3회와 검색이 필요해 E4보다 느렸다. 이미 평가에 사용한 자료이므로 새로운 통합 개선의 보류 검증셋으로 쓰지 않는다.
- `docs/results/E7_PREP_X2BEE_DATAFLOW_CANDIDATES_20260928.md`: 스키마에서 연결 가능한 후보를 추출했지만 실제 값 전달을 확인한 실행 관계는 아니다. 후속 호출/DONE/ASK 판단 모델은 후속 제안이다. 이를 검증된 작업 그래프로 가져오지 않는다.

## 브라우저 결과와 한계

- `docs/results/E13_REALTIME_FORMAT_20261004.md`: 사람 한국어 67개 항목에서 E13 실시간 정확도는 두 seed 평균 88.8%, 이전 E10은 세 seed 평균 75.6%다. 속도 판정은 실패했다. 이 수치를 새로운 사이트나 통합 작업 성공률로 일반화하지 않는다.
- `docs/results/A1_DEX_WIDE_BENCH_20261006.md`: 미학습 사이트 17곳의 명령 106개에서 E13 text 경로는 69/106, 65.1%였다. 실패 37개 중 실행기 원인이 14개로 기록되어 있다. 첫 실행 요소/입력 채점이므로 전체 업무 완료 검증과 다르다.
- 화면에 없는 대상의 오선택, 간접 표현, 이름 없는 아이콘, 가려진 요소, 접힌 검색창이 주요 실패다. 판단 모델과 실행기를 분리해서 개선해야 한다.
- E14는 사전등록과 실행 스크립트를 확인했으나 완료 결과 문서는 찾지 못했다. 최신 학습 완료·채택·서빙 상태는 미확인이다.
- E13 요소 선택 자체는 must-act 질문이다. 모든 화면 질문에 NONE이 이미 있다고 가정하지 않는다. 준비 판정의 `not_ui`도 'UI 요청이지만 대상이 없음'을 반드시 의미하지 않는다. 통합 시 후보 없음·추가 관찰·질문 전환을 호스트 수준에서 설계하고 별도 검증한다.

## 제안: 같은 도구 목록, 서로 다른 실행 바인딩

아래 항목은 일반 설계 제안이며 아직 xgen CLI에 구현하지 않았다.

```text
API 명세 / 브라우저 관찰
  → 공통 도구 정의와 근거 있는 관계
  → graph-tool-call: 작업 후보와 선행 도구 검색
  → xgen: 계획·권한·실행 대상 확인
     ├─ API 어댑터: API 호출
     └─ 브라우저 어댑터: 현재 화면 관찰
          → SEV: 현재 후보 중 대상 선택
          → browser-use 또는 agent-browser: 동작 실행
  → 실행 결과 재관찰·검증 → Receipt → 최종 응답
```

그래프에 영속 저장할 것은 재사용할 작업 정의, 입력·출력, 화면 조건, 이동·값 전달 관계와 근거다. 현재 화면의 `e12` 같은 요소 참조를 영구 도구 ID로 사용하지 않는다. 요소 참조는 세션·페이지·스냅샷 버전에 묶인 실행 바인딩이며, 실행 직전에 다시 확인한다. 화면별 임시 그래프를 사용해도 해당 수명을 보존한다.

API 결과에서 얻은 식별자를 브라우저 검색에 넣거나, 화면에서 얻은 식별자를 API 조회에 쓰는 관계도 표현할 수 있다. 단순 필드명 유사성은 후보 근거이며, 실제 값 전달·결과 확인으로 검증하기 전에는 확정 관계가 아니다.

SEV는 선택을 돕고 graph-tool-call은 후보와 관계를 찾는다. xgen이 효과 분류, 승인, 실행, 완료 검증을 소유한다. 클릭이라는 동작명이나 높은 confidence만으로 읽기 전용·권한·성공을 인정하지 않는다. API 실행이 시작된 뒤 실패했다고 브라우저로 자동 재실행하면 중복 효과가 생길 수 있으므로 기존 재개·중복 방지 정책을 따른다.

API 선택용 SEV 실험과 UI 선택용 E13은 서로 다른 학습·평가 경로다. 같은 프로토콜이라는 이유로 하나의 체크포인트가 두 작업을 잘한다고 가정하지 않는다. 초기 통합에서는 모델 선택을 어댑터 설정으로 분리한다.

## 다음 작업과 구성 요소별 추적

| 구성 요소 | 일반 개발 과제 | 검증할 것 |
| --- | --- | --- |
| xgen CLI | 공통 도구 계약과 실행 바인딩, 브라우저 관찰·판단·동작을 Receipt 경로에 연결 | 후보 밖 선택 거절, stale-ref 거절, 변경 효과 중복 방지, 최종 주장과 관찰 일치 |
| graph-tool-call | API와 화면 도구를 같은 목록에 수용, 근거·버전·효과 정보 보존 | 정답 후보 포함률, 잘못된 선행 관계, 검색 시간·스키마 크기 |
| SEV | 현재 화면 후보 선택 어댑터와 입력 형식 재사용, 판단 실패를 구분 | 올바른 대상 선택, 없는 대상의 오실행, 보류·질문 전환, 지연·모델 비용 |
| browser-use / agent-browser | 동일한 관찰·동작·결과 계약으로 연결 가능성 확인 | 팝업·가림·접힌 입력칸, 화면 변화, 동작 후 실제 결과 |
| 화면 변환 어댑터 | 관찰을 재사용할 작업 정의와 임시 요소 바인딩으로 분리 | 출처·버전, 화면 조건, 관찰·추론·검증 관계 구분 |

첫 실험은 조회 위주로 범위를 제한한다. 설계 사례와 새 검증 사례를 나누고 서로 다른 두 시스템에서 비교한다. 평가용 gold를 후보 구성에 넣지 않는다.

비교 순서:

1. 일반 브라우저 경로와 그래프를 참고하는 브라우저 경로를 비교한다. 관찰·실행기·모델은 고정한다.
2. 같은 후보에서 SEV 선택 추가 여부를 비교한다. 그래프와 실행기는 고정한다.
3. API와 화면을 잇는 조회 작업에서 값 전달·전체 완료를 검증한다.

모델 비교 실험은 SEV 규칙에 따라 새 사전등록을 먼저 만든다. 작업 완료율, 위험한 오실행, 후보 포함률, 클릭 대상 선택률, 실행 단계, 시간, 모델 호출·토큰·금액을 각각 기록한다. 모델 판단 정확도와 업무 완료율을 합치지 않는다.
