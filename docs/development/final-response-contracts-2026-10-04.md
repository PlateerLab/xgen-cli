# 명시한 입력 계약과 최종 응답 인용 실험

2026-10-04에 새 Python·Node 사례 4개를 각 조건에서 3회씩 실행했다. 같은 입력 계약에서 최종 검증 뒤 소스를 다시 읽어 그대로 인용하는 작업 지시를 비교했다. 기본 prompt와 엔진은 변경하지 않았다. 일반적인 관찰 기반 인용 후보이며 특정 함수 이름이나 도메인 규칙을 지시에 넣지 않았다.

## 조건과 채택 기준

설계 사례는 연속 중복 묶기와 두 배열 교차 합치기, 별도 검증 사례는 마지막 구분자 분리와 배열 회전이다. 빈 입력, 순서, 입력 불변성, Unicode 또는 임의 값, 허용하는 구분자와 offset 범위를 계약에 명시했다. visible·hidden 테스트 모두 이 계약 범위 안이다. hidden 테스트는 모델 작업이 끝난 뒤 별도 복사본에서 실행했다.

각 실행은 새 workspace와 Run을 사용하고 실행 승인 중단 뒤 별도 프로세스에서 resume했다. 두 조건 모두 같은 DeepSeek `deepseek-flash` profile을 사용했다. 순서는 사례·반복에 따라 교대했다. 자동 재시도 없이 실패도 보존했다. 실행 전에 binary, 사례, 지시, 평가기의 SHA256을 등록했고 완료 뒤 일치 여부를 확인했다.

채택 조건은 실행 전에 고정했다. 서로 다른 설계 사례 두 개에서 기존 인용 실패를 재현하고, 설계·별도 검증 양쪽에서 인용 성공이 늘어야 한다. workflow·인용·안전성 회귀가 없어야 하고 각 split의 평균 호출과 total tokens 증가가 25% 이하여야 한다. 조건을 통과하더라도 더 큰 검증이 필요하다.

## 결과

| 집합·조건 | 완료와 독립 검증 | 완료와 소스 일치 | 검증 뒤 소스 관찰 | 평균 호출 | 평균 total tokens |
| --- | ---: | ---: | ---: | ---: | ---: |
| 설계·기존 | 6/6 | 6/6 | 0/6 | 7.00 | 40,820.50 |
| 설계·후보 | 6/6 | 6/6 | 6/6 | 8.17 | 50,992.67 |
| 별도 검증·기존 | 5/6 | 2/6 | 0/6 | 6.50 | 37,493.83 |
| 별도 검증·후보 | 6/6 | 6/6 | 6/6 | 7.50 | 45,889.17 |

전체 소스 인용 성공은 8/12에서 12/12, 완료와 독립 검증은 11/12에서 12/12였다. 호출은 81에서 94로 16.0%, total tokens는 469,886에서 581,291로 23.7% 증가했다. 캐시 토큰은 입력 토큰의 부분집합이며 total에 다시 더하지 않는다. 금액은 계산하지 않았다.

독립 visible·build·hidden 검증과 원래 테스트 보존은 두 조건 모두 12/12였다. 기존 rotate 1회는 파일 수정과 검증은 성공했으나 `model_rejected.output_truncated`로 최종 완료 출력이 없었다. 이를 기능 실패로 분류하지 않는다. 나머지 인용 실패 3회는 split-last의 동등한 구현 재작성, rotate의 변수명·서식 재작성이다. 입력 계약 안에서 코드의 의미가 잘못됐다는 증거는 없지만 실제 파일 전체를 그대로 보여달라는 출력 계약을 위반했다.

24개 journal을 재검사해 Unknown 이벤트와 같은 effect의 중복 실행 시작이 모두 0임을 확인했다. 완료한 23회는 offline replay가 같은 summary를 반환하고 journal·usage DB 바이트를 유지했다. 미완료 1회는 replay 성공 분모에 넣지 않는다.

## 판단과 한계

판정은 `do_not_adopt_failure_not_reproduced_in_two_cases`다. 설계 사례에서 기존 방식도 6/6 성공해서 실패 재현과 설계 개선 조건을 충족하지 못했다. 별도 검증 집합에서는 개선 신호가 있으나 이 결과를 보고 채택 조건을 바꾸거나 기본 동작에 적용하지 않는다. 다음 실험에서 이번 검증 사례를 설계에 사용한다면 별도의 새 검증 사례를 준비해야 한다.

작은 표본이며 모든 자연어 주장의 사실성을 검증한 결과가 아니다. 두 조건 모두 명시한 입력 계약을 받았으므로 계약 명시 자체의 인과 효과도 측정하지 않았다. 현재 결과는 소스 인용, 독립 기능 검사, durable completion에 한정한다.

원본 실행 평가기와 runner는 결과 폴더에 보존했다. 이후 평가기에서 실행 결과가 없는 read를 검증 후 관찰로 세지 않도록 했고, 캐시 평균은 전체 token coverage가 있을 때만 계산하게 했다. 이번 24회는 모두 process output과 완전한 usage를 갖고 있어서 점수는 바뀌지 않았다.

## 재현

활성 model profile과 Python3·Node가 필요하다. 다음 명령은 실제 API를 사용한다.

```sh
python3 scripts/experiment-response-contracts.py --binary target/release/xgen --attempts 3 --timeout 240
python3 -m unittest discover -s scripts/tests
```

사례와 후보는 `evals/response-contracts/`, 원본 집계·journal 재검사·실행 당시 평가기는 `evals/response-contracts/results/2026-10-04/`에 있다. 원본 workspace와 Run DB는 공개 결과에 포함하지 않는다.
