# 여러 파일·소스 크기·응답 범위 비교

기본 prompt와 model profile을 바꾸지 않고, 기존 방식·항상 재확인·코드 인용 시에만 재확인을 비교한다. Python·Node의 두 작업군, 작은/큰 소스, 전체 소스 인용/검증 요약의 8개 조합을 조건별 2회 반복한다. 총 48회 실제 API 실행이며 자동 재시도는 없다.

각 작업은 두 소스를 수정한다. 작은 경우 두 파일 합계 약 250바이트, 큰 경우 약 22KB다. 크기 차이는 보존해야 하는 SOURCE_IDS 상수 데이터로 조절한 합성 fixture다. 생성기는 `build-cases.py`, 입력은 `cases.json`이다. 도메인 규칙이나 특정 함수 이름을 후보 지시에 넣지 않았다. 실제 대형 저장소 작업이나 일반적인 크기 효과를 대표하지 않는다.

전체 인용 조건은 두 파일 내용이 각각 코드 블록과 일치해야 한다. 요약 조건은 소스 코드 블록과 파일 전체 내용을 요청하지 않으며 명령·exit code·변경 파일 JSON만 요구한다. 이 출력 계약은 세 조건에 동일하다. 모든 명령은 실제 완료된 process output과 invocation recipe를 연결해 검증하고, 변경 파일은 작업 전후 내용으로 확인한다. 명령 설명 전체에 대한 범용 자연어 자동 검증은 아니다.

원래 테스트·설정 보존과 독립 visible/build/hidden 검증을 요구한다. Node build 명령은 첫 모듈의 구문 검사이며 두 모듈 모두 visible·hidden 테스트에서 import되어 구문·동작을 검사한다. 큰 소스의 상수 데이터가 삭제되거나 변경되면 hidden 검증이 실패한다.

사전 판정 기준은 8개 조합 모두 인용 시 재확인 후보의 응답 성공, 기존 대비 비회귀, 두 작업군의 인용 개선이다. 인용 작업의 평균 호출·total tokens 증가는 25% 이하, 요약 작업은 5% 이하, driver 시간은 30% 이하여야 한다. 요약 작업에서 항상 재확인 대비 token 절감도 요구한다. 작은 표본에서 이 기준을 통과해도 더 넓은 검증이 필요하다.

큰 파일이 출력 상한을 넘거나 파일 수정 단계부터 실패하면 인용 실패와 구분해 기록한다. 모델의 현재 inference limits를 높여 통과시키거나 실패를 제거하지 않는다. 미완료 응답을 완료한 응답의 인용 오류로 분류하지 않는다.

```sh
python3 scripts/experiment-response-scaling.py --binary target/release/xgen --attempts 2 --timeout 240
python3 -m unittest discover -s scripts/tests
```

실행 전에 binary·입력·생성기·후보·평가기 SHA256과 기준을 등록하고 끝에 재확인한다. 조건 순서는 조합·반복에 따라 교대한다. driver 시간은 최초 실행과 승인 후 resume 시간이며 독립 검증·offline replay는 제외한다. provider 시간은 usage의 호출 시간 합계다. 캐시 토큰은 total에 중복 합산하지 않으며 금액·통계적 유의성·전체 자연어 응답 정확도를 주장하지 않는다.
